# Зонд co-op для Far Cry 3 (русский)

> English: [README.md](README.md)

> **Статус:** ранний исследовательский зонд (Фаза 2, хук H1). Не рабочий co-op-мод.

## Что это

Первый **зонд-инъектор** проекта co-op для Far Cry 3. Это 32-битный прокси `dinput8.dll`:
движок (`FC3.dll` / `FC3_d3d11.dll`) импортирует `dinput8.dll`, поэтому `dinput8.dll`,
положенный рядом с игрой, загружается первым. Прокси:

1. перенаправляет все шесть экспортов `dinput8` настоящему системному `dinput8.dll` (игра
   по-прежнему запускается), и
2. запускает фоновый поток, который пишет id co-op-сессии `0x43521E6F` в две глобальные
   переменные движка, в которых, как доказала Фаза 1, хранится активный id сессии.

Это хук **H1** из плана — *самый дешёвый первый эксперимент*: форсировать co-op id в рантайме и
посмотреть, войдёт ли игра в co-op-состояние (хост). Он пишет только два глобальных двойных
слова, поэтому не может испортить сохранение, но это непроверенный эксперимент: движок может
перезаписать значение своей инициализацией, или двух глобальных переменных может не хватить для
играбельного co-op. Именно это он и призван выяснить.

## Раскладка

```
mod/fc3coop_probe/
  fc3coop_probe.c   исходник: DllMain, 6 перенаправителей, поток-зонд (дизайн — в комментарии сверху)
  dinput8.def       экспортирует 6 имён по порядковым 1..6 (именно этот набор держит игру живой)
  build.bat         сборка MSVC x86 -> build/dinput8.dll
  verify_build.py   проверяет собранный DLL: x86 + 6 экспортов на порядковых 1..6
  build/            (вне git) сюда кладётся собранный dinput8.dll
```

Исходники в git; бинарники (`build/`) и логи вне git.

## ASLR — почему код использует base + RVA

`FC3.dll` собран с ASLR (`DllCharacteristics=0x0140`, таблицы перемещений есть, предпочтительная
база `0x10000000`). Любой VA в `NOTES.md` — это VA только в предпочтительной базе. Зонд читает
живую базу модуля в рантайме (`GetModuleHandleW`) и прибавляет RVA (`VA − 0x10000000`):

| Смысл | VA в предпочт. базе | RVA, которое использует зонд |
|---|---|---|
| глобал co-op id 1 | `0x12891ca0` | `+0x2891CA0` |
| глобал co-op id 2 | `0x12891ca8` | `+0x2891CA8` |
| значение co-op id | — | `0x43521E6F` |

## Сборка

```
cd mod/fc3coop_probe
cmd //c build.bat        # нужны x86-инструменты Visual Studio (vcvars32.bat)
python -I verify_build.py
```

На выходе `build/dinput8.dll` (x86, статическая CRT `/MT`). `verify_build.py` обязан напечатать
`EXPORTS CHECK : PASS` с шестью именами на порядковых 1..6 и `machine 0x14C`.

Проверенная сборка (2026-11-07): `build/dinput8.dll`, 115 200 байт, `machine=0x014C`,
`DllCharacteristics=0x0140`, экспорты `DirectInput8Create@1, DllCanUnloadNow@2,
DllGetClassObject@3, DllRegisterServer@4, DllUnregisterServer@5, GetdfDIJoystick@6`.

## Установка и запуск (это делает владелец — здесь не автоматизируется)

1. Скопировать `build/dinput8.dll` в папку `bin` **рабочей копии** игры
   (`H:\FarCryCoop\TestFC3\bin\`). Никогда в настоящую установку (`H:\Uplay\Far Cry 3\`
   по правилу проекта — только для чтения).
2. Запустить игру как обычно и загрузиться в одиночную игру.
3. Открыть `binc3coop_probe.log`. Теперь он логирует достаточно, чтобы ответить на H1 из
   *одного* запуска:
   - `FC3 coop probe: engine base = 0xXXXXXXXX (from FC3.dll)` — зонд загрузился и нашёл движок.
   - `pre-poke default: [g1]=0xAAAAAAAA [g2]=0xBBBBBBBB` — значение, которое движок держал *до*
     нашего вмешательства (одиночная «по умолчанию»). Показывает, что обычная игра хранит там.
   - `poke n/5: ... readback [g1]=0x... [g2]=0x...` — после каждой форсированной записи значение,
     прочитанное обратно. Если readback равен `0x43521E6F` — запись закрепилась; если снова видно
     старое значение — движок перезаписал нас (одного H1 недостаточно).
   - `OVERWRITE: readback ...` / `heartbeat poke #N ...` — периодическое подтверждение, держится ли значение.
4. Посмотреть, сообщает ли игра о co-op-состоянии (хост) или меняет поведение.

Если игра не запустилась — удалить `dinput8.dll` из папки `bin`, игра восстановится.

## Безопасность

- Не трогает настоящую установку игры и сохранения.
- Пишет только два глобальных двойных слова в сегменте данных движка, под `VirtualQuery` +
  `VirtualProtect` + SEH, поэтому неверный указатель не может уронить игру.
- Перенаправление прозрачно; удаление DLL полностью восстанавливает игру.
