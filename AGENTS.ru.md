# Правила проекта для кодинг-агента
Версия на английском (канонический текст): [AGENTS.md](AGENTS.md). Этот файл — его русская пар.
Это канонический файл инструкций. Агентская программа (Pi) автоматически подгружает `AGENTS.md`
из рабочей папки и из каждой вышестоящей папки, перебирая имена в таком порядке:
`AGENTS.override.md`, `AGENTS.md`, `AGENTS.MD`, `CLAUDE.md`, `CLAUDE.MD`. Значит этот файл читается
агентом сам в каждой сессии; `CLAUDE.md` в репозитории — только ссылка на него.
## Золотое правило
ВСЕГДА писать документацию и любые другие тексты проекта для людей (README, заметки, руководства,
комментарии в документах, описания issue/PR) на ДВУХ языках: русском и английском. Без исключений.
Использовать пару файлов `NAME.md` (английский) + `NAME.ru.md` (русский) или оба языка в одном файле
для коротких текстов. Если меняется одна языковая версия, обнови другую в том же коммите.
## Золотое правило 2: рабочая папка
Работать только в путях из раздела «Рабочая папка на этом ПК» ниже. НИКОГДА ничего не читать, не
писать и не скачивать на диск C: — без исключений. НИКОГДА не качать в `%TEMP%`. Игровую установку не
изменять (`H:\Uplay\Far Cry 3\` — только чтение); работать с копией `H:\FarCryCoop\TestFC3\`. Черновые
файлы — только в папках вне git (`local/scratch/`, `Temp/`, `*.scratch*`). Если шаг требует диска C:,
остановиться и спросить владельца. Одно отклонение неустранимо и принято владельцем: агентская
программа пишет свои временные файлы и выводы делегатов в
`C:\Users\<user>\AppData\Roaming\pi-desktop\` — отмечено, не исправлено, см. docs/workspace.md.
## Коммиты
Сообщения коммитов пишутся по Conventional Commits (https://www.conventionalcommits.org/en/v1.0.0/) и
только на английском: `<тип>(<область, необязательно>): <описание>`, например
`docs(far-cry-6): add research notes`. Типы: feat, fix, docs, chore, refactor, test, build, ci, perf,
style, revert.

## Механика сессии
Вызовы инструментов: один блок на ход, один инструмент в блоке, аргументы не больше ~4 КБ. Длинные
probe-скрипты писать в файл и запускать короткой командой (`python -I scripts/<имя>.py`), не вставлять
код в вызов; читать файлы частями по номерам строк, не целиком. Конвенно: `Read(offset=42, limit=30, path="<файл>")`;
чтобы перейти к нужной области, сначала `grep -n <шаблон> <файл>`, потом читать с этого номера строки.
Запросы к модели: запускать ОДИН запрос к модели за раз (суб-агент, веб-поиск, проверка источников) и
ждать его результат перед следующим — запросы к модели обрабатываются последовательно.
Правила владельца не переписывать молча: сообщать о расхождении и решать владельцу.

## ⚠️ Обязательное использование Supermemory (MCP)
Проектная память живёт в **supermemory MCP** (тег/контейнер проекта: `FarCry3Coop`).
Это **дополняющий** слой поверх `docs/` и других документов `*.md` (доки остаются источником истины —
держать их и память в sync).

- **Начало работы:** перед стартом задачи делать **`recall`** по supermemory (запрос по тематике
  фичи/модуля, `containerTag: FarCry3Coop`) — чтобы восстановить контекст: стек, архитектуру,
  механики, схему БД, конвенции, известные проблемы, текущую версию.
- **По ходу / по завершении:** при изменении состояния проекта (новая фича/версия, смена
  механики, схемы БД, команд, зависимостей, деплой, новая проблема/долг) **сохранять**
  актуальные сведения в supermemory (**`save`**, `containerTag: FarCry3Coop`). Не плодить
  мелочь — обновлять тематические записи (обзор/стек · архитектура · механики · команды ·
  схема БД · PRNG/кубики · конвенции · проблемы/долг · текущее состояние).
- Если в памяти устарело (изменилась версия, сервер, механика) — **перезаписать** запись
  (`memory` действие `replace` с идентификатором записи), а не добавлять рядом старую.

Цель: любой агент по `AGENTS.md → supermemory (recall) → docs` мгновенно понимает
состояние проекта, даже без полного перечитывания доков.

## Особенности инструментов на этом ПК
- Инструменты `ctx_*` работают под PowerShell: `&&` и `||` — синтаксическая ошибка, `>` пишет в UTF-16,
  `2>/dev/null` создаёт `D:\dev\null`. Несколько команд — только через bash.
- Инструмент правки портит кириллицу: русский текст писать bash-heredoc'ом со вставкой через Python.
- Консоль на этом ПК в кодировке cp1251: кириллицу выводить через
  `sys.stdout.buffer.write(...encode('utf-8'))`.
- Python в игровых папках запускать как `python -I` (в папке игры есть `python3.dll`, который иначе
  ломает `python.exe`).
- `gh api --jq` не понимает выражения со скобкой `(`; JSON пропускать через `python -c`, дампы PowerShell
  декодировать как UTF-16.
- В bash-heredoc'е backslash внутри строковых литералов Python искажается: собирать через `chr(92)`.
